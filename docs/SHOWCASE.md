# 三分钟演示：从问题到可追溯来源

这份指南用于本地演示和面试介绍。默认模式使用 **6 条人工编写的流程说明**，通过摘录展示检索、接口、页面和图引用的完整交互。它适合展示工程行为，**不代表医学准确率、临床验证结果或大模型生成质量**。

## 演示前准备

1. 按项目 [README](../README.md) 的“快速体验”完成安装和示例数据准备。
2. 在项目根目录启动服务：

   ```bash
   python -m uvicorn medical_rag.app:app --host 127.0.0.1 --port 9001
   ```

3. 打开 <http://127.0.0.1:9001/dr/demo>，确认右上方显示 **API 已连接**，页面显示 **本地示例模式**。
4. 保持“候选片段”为 **10 条**、“最终来源”为 **3 条**。页面上的例题按钮会填入问题；点击 **检索并回答** 才会发送查询。

图引用使用项目内的人工流程图 `examples/workflow.svg`。示例准备步骤会将其复制到配置的图片目录，默认是 `data/images/`；如果图未出现，先核对该准备步骤是否执行。

## 三分钟演示顺序

| 时间 | 页面操作 | 可以说明的工程能力 |
| --- | --- | --- |
| 0:00–0:20 | 展示页面标题、运行模式和右侧流程 | 平台围绕“提问 → 检索与重排 → 组织回答 → 核对来源”组织交互。当前运行的是人工流程样例。 |
| 0:20–0:55 | 点击 **如何核对回答的来源？**，再点击 **检索并回答** | 文本问题通过 `/dr/chat` 进入服务，回答与来源一并返回，页面显示本次请求耗时。 |
| 0:55–1:30 | 展开阅读回答下方的来源卡片 | 指出来源编号、文件名、页码、文本摘录及检索分数。检索分数表示相关性，不能解释为医学结论的可信概率。 |
| 1:30–2:00 | 点击 **图引用代表什么？**，再提交 | 展示来源卡片中的流程图和图注。图片来自已关联的本地资料，这个接口接收文本问题，不执行用户图片的临床诊断。 |
| 2:00–2:30 | 指出回答下方的运行标记，再看 **启用相关性重排** 开关 | 是否实际重排以结果中的标记为准。默认示例检索不需要下载嵌入模型或重排模型；开启开关不等于已经调用真实重排模型。 |
| 2:30–3:00 | 点击右上角 **API 文档 ↗** | 展示可复用的 HTTP 接口、参数约束和结构化返回。说明真实知识库、向量检索、重排与模型服务通过配置接入。 |

示例卡片中的 PDF 文件名和页码是**用于演示来源字段的人工元数据**，不对应仓库中已收录的真实医学 PDF。面试时可以直接说：“这里先展示不依赖 GPU 的工程交互；真实文献和模型服务使用同一套问答接口接入。”

## 怎样解释代码结构

可以从用户操作沿着调用链介绍三个位置：

1. [`web/index.html`](../web/index.html)：原生 HTML/CSS/JavaScript 实现页面，展示回答、引用和错误状态；不依赖外部 CDN。
2. [`src/medical_rag/app.py`](../src/medical_rag/app.py)：定义 API、请求校验、结构化来源和受限的本地图片访问。
3. [`src/medical_rag/pipeline.py`](../src/medical_rag/pipeline.py)：串联检索、可选重排与回答生成，区分示例模式和真实后端。

`/health` 报告 API 进程和初始化状态。**API 已连接不等于真实模型服务与向量库已经通过可用性检查**；真实依赖是否可用要结合实际查询和服务日志确认。查询失败会返回错误，页面不会把异常显示成成功回答。

## 切换到真实后端

真实模式需要先准备有权使用的文档、完成索引构建，并启动匹配的模型服务。具体部署与数据处理命令以 [README](../README.md) 为准。以下是需要对齐的主要配置，不应只修改模式开关就声称已经完成真实模型验证：

| 配置 | 含义 |
| --- | --- |
| `MEDRAG_MODE=live` | 启用真实后端。默认值 `demo` 用于人工流程样例。 |
| `MEDRAG_DATA_DIR` | 文档、索引与图片所在的数据目录，默认 `data/`。 |
| `MEDRAG_MILVUS_URI` | Milvus 服务地址或受支持环境中的 Milvus Lite 数据库路径。 |
| `MEDRAG_COLLECTION` | 检索所使用的 collection，需与建库时一致。 |
| `MEDRAG_EMBEDDING_MODEL` | 向量化模型，需与建库时一致。 |
| `MEDRAG_RERANKER_MODEL` | 真实重排模型。 |
| `MEDRAG_LLM_BASE_URL` | 兼容 OpenAI 接口的模型服务地址，例如 `http://127.0.0.1:8001/v1`。 |
| `MEDRAG_LLM_MODEL` | 与模型服务公开的模型名称一致。 |
| `MEDRAG_LLM_API_KEY` | 模型服务需要鉴权时，通过本地环境变量提供。 |

修改环境变量后重启 API。页面会显示 **真实知识库模式**；完成真实查询后，再查看来源及重排标记。不要用本地示例的耗时推断 GPU 模型服务的性能。

## 验证结果在哪里看

- 查看发布时的 [验证记录](../reports/VALIDATION.md) 与 `reports/demo_eval.*`，了解已保存的验证范围和人工样例评估输出；完整流程见 [评估说明](EVALUATION.md)。用户重新运行评估时，默认将结果写入 `data/eval-runs/`。
- 工程测试检查接口、数据结构、错误处理和路径边界；测试通过不等于医学回答准确率已经测量。
- 本次发布的人工示例没有对应的医学评测集，也没有可以据此报告的医学准确率或模型优越性结论。
- 真实评估应记录使用的语料版本、问题集合、模型与索引配置，并保留逐条结果。介绍数字时应能够指出对应的结果文件。

## 可以直接使用的项目介绍

> 我把医疗文献问答整理为检索、可选重排、模型服务和来源展示四个环节。页面不仅展示回答，还返回文本摘录、文件名、页码和关联图示，便于核对出处。默认演示使用人工流程样例，无需 GPU，可以现场运行；真实后端通过配置接入 Milvus 和模型服务。发布仓库保留了工程测试和验证说明，医学效果需要在明确的文档和问题集合上单独评估。
