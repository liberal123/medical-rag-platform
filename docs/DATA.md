# 数据与来源约定

仓库内的 `examples/demo_knowledge.jsonl`、`examples/eval_demo.jsonl` 和 `examples/workflow.svg` 是人工编写的工程示例。样例中的 PDF 文件名和页码用于演示字段，没有对应的第三方医学原文，也不构成医学知识库。

真实运行时，将有权使用的 PDF 放入本地 `data/pdfs`，执行导入命令。仓库不提供患者记录、第三方全文、模型权重或已建好的医学索引。

## 知识记录

```json
{"text":"原文片段", "source_file":"guideline.pdf", "page":3, "source":"DR_PDF"}
```

- `text`（也兼容 `content`）：待向量化文本。
- `source_file`：相对 PDF 输入目录的文件名或路径。
- `page`：从 1 开始的 PDF 物理页码，可能不同于文献印刷页码。
- `image_path`：可选，相对图片根目录的路径。
- `caption/context`：可选，图片附近的候选图注和页面文字。

默认每块 500 字符，重叠 80 字符，不跨 PDF 页面。图片最小尺寸默认 120×120；候选图注由同页距离图片较近的文字块推断，必须人工核对。图片本身不经过视觉编码器；无文字扫描件需要先另行 OCR。没有图注或页面文本的图片不进入文本向量索引。

导入索引和评估记录均拒绝覆盖已有文件；更换输出目录即可保留新旧版本。索引构建拒绝覆盖已有 Milvus collection。请保留资料名称、出版日期、授权情况和内容哈希，以追溯实际使用的语料版本。

中文补充条目可按相同 JSONL 格式另建文件，再通过重复的 `--input` 参数合并建库。引用必须指向真实资料，不能仅把模型生成的摘要标作已核验医学结论。

## 第三方依赖

依赖及模型遵循各自许可。尤其 PyMuPDF 的开源/商业授权、GLM 和 BGE 模型许可应按实际使用方式检查。当前仓库未添加一份覆盖所有外部资料的统一开源授权。
